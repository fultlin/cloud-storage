# Проверка бэкенда — 5 ноября 2026

Основание: разделы 10.1–10.3 и критерии этапа 1 технического задания.

## Подтверждено автоматическими проверками

- Сборка API и web, oxlint, строгая проверка типов.
- Общие схемы авторизации и путей: 87 тестов.
- Пользователи, миграции на чистой тестовой PostgreSQL, Argon2, Redis-сессии,
  регистрация, вход, выход, глобальная защита маршрутов.
- Файловые маршруты без сессии возвращают 401. Невалидные пути отклоняются
  на всех принимающих путь операциях, включая from и to перемещения.
- SeaweedFS: запись, метаданные, листинг, поиск, копирование, удаление,
  Unicode-имена, изоляция пользователей и конфликты при записи.
- Пагинация поиска и листинга, пачки удаления более 1000 ключей проверены
  на подменённых ответах AWS SDK, а не на 1000 реальных объектах.
- HTTP-загрузка: UTF-8, вложенные пути, лимиты, откат дубликата в запросе.
- Скачивание: заголовок Content-Disposition, ZIP с относительными именами,
  пустые папки. Ошибка посреди передачи файла обрывает HTTP-ответ.
- Swagger/OpenAPI и генерация типов; e2e-проверка флага документации и
  совпадения опубликованного документа со снимком фронтенда.

## Исправление, найденное при проверке

Рекурсивное удаление на SeaweedFS могло оставить папку при наличии вложенного
файла. Теперь сначала удаляются файлы, затем маркеры от самых глубоких к корню.
Регрессионный тест содержит вложенную папку с настоящим объектом.

## Открытые критерии и ограничения

- SeaweedFS 4.48 не гарантирует сосуществование файла и одноимённой папки
  в используемой модели ключей. Это несоответствие контракту, а не пройденный
  критерий. Перед приёмкой нужен совместимый провайдер или изменение слоя хранения.
- StorageService: передача 2 ГиБ в обе стороны выполнена на временном SeaweedFS.
  Размер и SHA-256 совпали; прирост RSS процесса теста не превысил 512 МиБ.
  Данные генерировались потоком, без сохранения исходного файла на диск. Проверка
  заняла около минуты. Это не замер процесса API при HTTP-загрузке: прогон через
  HTTP и замер RSS отдельного процесса API подтверждены следующим прогоном.
- Ручная проверка кириллицы внутри ZIP в архиваторах Windows и macOS не выполнена.
- Все операции и каждый код ошибки вручную через Swagger UI ещё не проверены.
- Конкурентные изменения одного дерева при move не поддерживаются транзакционно.
- Пагинация и удаление 1000+ реальных объектов требуют отдельного прогона.

Зелёные тесты не означают закрытие перечисленных критериев приёмки.

## Дополнительная диагностика провайдера

SeaweedFS 4.52 проверен в отдельном временном контейнере. Запись файла `same`
после создания `same/` также вернула 409. Поэтому Compose остаётся на 4.48:
обновление версии не устраняет подтверждённое несоответствие само по себе.
Добавлен тест, фиксирующий текущее ограничение; он не доказывает выполнение
контракта сосуществования файла и папки.

## Передача 2 ГиБ через HTTP

Команда: `pnpm --filter @app/api verify:large-http`.
Изолированные PostgreSQL, Redis и SeaweedFS 4.48; отдельный Node.js 24.14.0
для API. Выполнены миграции, регистрация, multipart-загрузка (201) и потоковое
скачивание (200). SHA-256 исходного и скачанного файла совпали.

- Размер: 2 147 483 648 байт.
- RSS API перед передачей: 180 879 360 байт.
- Максимальный RSS API (выборка раз в 100 мс): 306 106 368 байт.
- Прирост RSS: 125 227 008 байт, около 119,4 МиБ.
- Загрузка и скачивание: около 56 секунд.

Числа относятся к этому прогону, а не являются гарантированным верхним пределом.
Данные клиента не включены в замер API. nginx в проверке не участвовал.
Машинный отчёт: `apps/api/verification/large-http.json`.
