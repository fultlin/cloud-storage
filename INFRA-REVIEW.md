# Проверка инфраструктуры

Основание: разделы 10.5, 11, 12 и критерии этапа 3 ТЗ.

## Подтверждено

- Docker Engine восстановился после остановки Docker Desktop и WSL, создания
  проверенной копии диска и холодного запуска. Старый базовый образ Node
  завершался с кодом 139 даже на `node --version`. Образы пересобраны на Node
  24.14.1; runtime запускается с UID 1000, без исходников приложения и без
  прямых dev-зависимостей. Мигратор и подготовка бакета завершились с кодом 0.
- Compose проверен с тестовыми значениями: в локальном и серверном вариантах
  публикуется только nginx. Серверная конфигурация требует внешнего S3 и
  обязательных секретов. Миграции запускаются отдельным контейнером.
- nginx 1.30.6 для Windows: вложенный маршрут возвращает SPA, отсутствующий
  ассет — 404, префикс /api сохраняется. Отдельная проверка доказала передачу
  первой части запроса и ответа до завершения соответствующего потока.
- Скрипт `verify:large-nginx` передал 1 073 741 824 байта в обе стороны через
  тот же nginx. SHA-256 клиента и независимого тестового upstream совпали:
  `3d4f5e43b42cc2bb6a18381a696d0ebf4d8baf6644c9e5fd7a1e357b56eced56`.
  Upstream генерировал данные и сверял хеш; SeaweedFS и PostgreSQL не участвовали.
- Полный Compose прошёл браузерный `test:full`: регистрация через nginx,
  загрузка папки, F5, содержимое файла и ZIP, поиск, выход и флаги cookie.
- `verify:large-nginx` прошёл и на полном Compose с PostgreSQL, Redis и
  SeaweedFS: 1 073 741 824 байта загружены и скачаны за 13,38 секунды, SHA-256
  совпал с указанным выше. Это проверка транспорта, не измерение прогресса UI.
- Для локального SeaweedFS лимит слотов увеличен до 16. С лимитом 5 служебная
  коллекция заняла все слоты, и S3 не мог выделить volume для `user-files`.
- Браузерный сценарий `FULL_STACK_LARGE_UPLOAD=true` прошёл за 23,6 секунды:
  Chromium показал промежуточный прогресс (1%), API вернул 201, а файл размером
  1 ГиБ появился в списке без F5. Скриншот сохраняется в результатах Playwright.
- Linux-стадия `production-dependencies` установила зависимости из обновлённого
  lockfile и подтвердила отсутствие Prisma CLI и TypeScript. Генерация Prisma
  Client и сборка NestJS на хосте прошли с тем же lockfile.
- После переноса диска Docker Desktop на другой накопитель полный Compose
  пересобран с существующими volumes. Мигратор и подготовка бакета завершились
  с кодом 0. Swagger JSON доступен через nginx при `SWAGGER_ENABLED=true`,
  браузерный `test:full` прошёл. Готовый образ API весит 569 847 624 байта
  (543 МиБ), раньше весил 899 709 420 байт (858 МиБ). Проверка внутри образа
  подтвердила UID 1000 и отсутствие Prisma CLI и TypeScript.
- Локальная репетиция `compose.prod.yaml` по инструкции для VPS прошла на
  чистой PostgreSQL с отдельным экземпляром SeaweedFS в роли внешнего S3.
  Мигратор применил схему, повторный запуск подтвердил отсутствие ожидающих
  миграций. Только nginx публиковал порт. Через него `/api/user/me` без
  сессии вернул 401, отключённый Swagger вернул 404, а `test:full` прошёл
  с реальными загрузкой и скачиванием. Контейнеры и volumes репетиции удалены.
