# Проверка инфраструктуры

Основание: разделы 10.5, 11, 12 и критерии этапа 3 ТЗ.

## Подтверждено

- Docker собрал Linux-образы runtime API, migrator и web. При создании
  контейнеров движок затем вернул ошибку ввода-вывода, поэтому это подтверждает
  сборку, но не запуск образов.
- Compose проверен с тестовыми значениями: в локальном и серверном вариантах
  публикуется только nginx. Серверная конфигурация требует внешнего S3 и
  обязательных секретов. Миграции запускаются отдельным контейнером.
- nginx 1.30.6 для Windows: вложенный маршрут возвращает SPA, отсутствующий
  ассет — 404, префикс /api сохраняется. Отдельная проверка доказала передачу
  первой части запроса и ответа до завершения соответствующего потока.
- Скрипт `verify:large-nginx` передал 1 073 741 824 байта в обе стороны через
  тот же nginx. SHA-256 клиента и независимого тестового upstream совпали:
  `3d4f5e43b42cc2bb6a18381a696d0ebf4d8baf6644c9e5fd7a1e357b56eced56`.
  Upstream генерировал данные и сверял хеш; SeaweedFS и PostgreSQL не участвовали.

## Остаётся проверить

1. После восстановления Docker запустить полный Compose и убедиться, что
   migrator и s3-init завершились с кодом 0, а API работает от пользователя node.
2. На полном Compose выполнить `pnpm --filter @app/web test:full` и
   `pnpm --filter @app/api verify:large-nginx`. Отдельно проверить прогресс
   большой загрузки в браузере. Обе команды описаны в README.
3. Развернуть на VPS с выбранным внешним S3, проверить приложение по ссылке
   и совместимость S3 с требуемыми операциями. Публичный HTTPS ещё не настроен.

Во время проверок существующие Docker volumes не удалялись.
