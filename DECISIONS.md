# Архитектурные решения

## 003. Валидация окружения при старте

Решение: ConfigModule получает Zod-схему через validationSchema. Тип Env
выводится из результата схемы; приложение получает значения через ConfigService.
Путь к корневому .env вычисляется относительно app.module, а не текущей папки терминала.
В контейнере переменные могут передаваться без .env через окружение процесса.

Альтернативы: прямое чтение process.env или отдельный ручной валидатор.

Причина: неверные настройки останавливают запуск, строки boolean разбираются
явно, типы и проверка значений описаны одной схемой. Серверная конфигурация
остаётся в API и не экспортируется в браузерный shared.

Основание: раздел 8.1 ТЗ.

## 001. Общий пакет в pnpm workspace

Решение: приложения `@app/api` и `@app/web` используют локальный пакет
`@app/shared` через зависимость `workspace:*`.

Альтернативы: отдельные репозитории или копирование схем в каждое приложение.

Причина: общие схемы и типы живут в одном месте, а workspace-протокол требует
локальный пакет и исключает подмену этой зависимости пакетом из реестра.

Основание: раздел 5 ТЗ.

## 002. Инициализация приложений

Решение: официальные шаблоны Nest CLI 12 (ESM/Vitest) и create-vite (React TypeScript).
TypeScript 6.0.2 используется во всём workspace, как в сгенерированных шаблонах.

Альтернатива: вручную собранный каркас или TypeScript 7 без проверки совместимости.

Причина: используем стартовые настройки генераторов; oxlint вынесен в корень.
В разработке Vite проксирует /api без удаления префикса на NestJS, сохраняя один origin.

Основание: разделы 4, 5 и 8.0 ТЗ.

## 004. Локальная инфраструктура через Compose

Решение: PostgreSQL, Redis и SeaweedFS запускаются в отдельных контейнерах;
API и web остаются локальными процессами. Теги образов фиксированы.
Данные каждого сервиса хранятся в отдельном именованном volume.
Redis использует AOF, SeaweedFS хранит данные и метаданные filer в /data.
S3-ключи передаются через env; бакет создаётся отдельной административной командой.

Альтернатива: установка сервисов на Windows или контейнеризация приложений уже сейчас.

Причина: воспроизводимая инфраструктура без усложнения отладки приложений.
Порты опубликованы только на 127.0.0.1. Полный стек с nginx добавим на этапе деплоя.

Основание: разделы 8.5 и 11 ТЗ.
