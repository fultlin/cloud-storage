# Проверки и приёмка

Результаты локальных прогонов по разделам 10–12 ТЗ. Команды описаны в
[README](README.md#проверки), причины архитектурных решений — в [DECISIONS.md](DECISIONS.md).

## Автоматические проверки

- Финальный локальный прогон: `pnpm lint`, `pnpm typecheck`, 340 тестов
  пакетов (87 shared, 209 API, 44 web) и 2 API e2e. Опциональный тест передачи
  2 ГиБ через StorageService не входил в этот прогон.
- API проверен на изолированных PostgreSQL, Redis и SeaweedFS. Тесты покрывают
  миграции, сессии, защиту маршрутов, валидацию путей, изоляцию пользователей,
  конфликты загрузки, скачивание ZIP и обрыв ответа при ошибке потока.
  Пагинация и удаление более 1000 ключей проверены с подменёнными ответами SDK.
- API e2e сверяет опубликованный OpenAPI с [фронтенд-снимком](apps/web/openapi.json).
  Браузерные проверки с MSW покрывают основные операции и потерю сессии.
- Playwright через nginx и полный Compose проверил регистрацию, загрузку
  папки с кириллицей, F5, переименование, перемещение, поиск, удаление, выход
  и флаги cookie. Содержимое скачанного файла и ZIP сверено с фикстурой.

## Большие файлы

| Прогон | Результат |
| --- | --- |
| 2 ГиБ через StorageService | Размер и SHA-256 совпали. Прирост RSS процесса теста не превысил 512 МиБ. |
| 2 ГиБ через HTTP API | Загрузка и скачивание за 55,9 секунды, SHA-256 совпал. RSS API вырос с 172,5 до 291,9 МиБ. [Машинный отчёт](apps/api/verification/large-http.json) |
| 1 ГиБ через nginx и полный Compose | Передача в обе стороны за 13,38 секунды, размер и SHA-256 совпали. |
| 1 ГиБ через Chromium | Промежуточный прогресс 1%, ответ API `201`, файл появился без F5. Прогон занял 23,6 секунды. |

Отдельная проверка nginx с тестовым upstream подтвердила, что первая часть
запроса и ответа передаётся до завершения соответствующего потока. Замеры
относятся к отдельным локальным прогонам.

## Серверная конфигурация

- Runtime-образ API проверен изнутри. Он работает с UID 1000 и весит 543 МиБ
  вместо 858 МиБ. В нём отсутствуют исходники приложения, Prisma CLI и TypeScript.
- `compose.prod.yaml` локально запущен с чистой БД и отдельным SeaweedFS в роли
  внешнего S3. Первый запуск мигратора применил схему, повторный завершился
  без новых миграций. Порт публиковал только nginx. Через него `test:full`
  прошёл, запрос без сессии вернул `401`, отключённый Swagger — `404`.
- HTTPS проверен локально с временным сертификатом, которому доверял тестовый
  клиент. HTTP вернул `308` на заданный адрес с исходным путём и query при
  подменённом `Host`. По HTTPS открылась вложенная страница, регистрация
  выдала cookie `Secure`, `HttpOnly`, `SameSite=Lax`, запрос с cookie вернул профиль.

## Открытые пункты приёмки

- Публичное развёртывание на VPS и проверка выбранного внешнего S3. SeaweedFS
  4.48 и 4.52 вернули `409` при записи файла `same` после создания папки
  `same/`. Сосуществование таких ресурсов нужно подтвердить на целевом S3.
- Пагинация и удаление более 1000 реальных объектов у выбранного провайдера.
- Ручная проверка имён в ZIP штатными архиваторами Windows и macOS и полный
  ручной прогон операций и кодов ошибок через Swagger UI.
